# 网站缓存问题排查与解决

## 问题描述

线上部署后，页面图片地址没有正确拼接 `NEXT_PUBLIC_IMAGE_BASE_URL`（`https://claude.artimg.top`），导致图片请求走了 Next.js 内置的 `/_next/image` 代理，返回 404。

**表现**：图片 URL 为 `/temp/2026-04-02/xxx.png`，期望为 `https://claude.artimg.top/temp/2026-04-02/xxx.png`。

## 排查过程

### 1. 确认环境变量配置

`.env.production` 中已正确配置：

```env
NEXT_PUBLIC_IMAGE_BASE_URL=https://claude.artimg.top
```

`NEXT_PUBLIC_` 前缀的变量会在 **构建时** 被 Next.js 内联到 JS bundle 中，不是运行时读取。

### 2. 确认构建产物

本地执行 `pnpm build` 后，在 `.next/static/chunks/pages/` 中搜索，确认 `claude.artimg.top` 已被正确内联到 JS bundle 中。

### 3. 定位根本原因 —— Nginx 代理缓存

服务器 Nginx 全局配置了 `proxy_cache`：

```nginx
# /www/server/nginx/conf/proxy.conf
proxy_cache_path /www/server/nginx/proxy_cache_dir levels=1:2 keys_zone=cache_one:20m inactive=1d max_size=5g;
proxy_cache cache_one;
```

**这导致了两个问题**：

1. 旧版本构建的 JS bundle（未内联 `IMAGE_BASE_URL`）被 Nginx 缓存，新构建部署后用户仍然拿到旧的 JS 文件
2. 即使停掉 PM2 服务，页面仍然可以正常访问（Nginx 直接返回缓存内容）

### 4. 验证缓存是问题根源

```bash
# PM2 停了，直接访问后端返回连接拒绝
curl -I http://127.0.0.1:3100  # Connection refused

# 但通过域名访问仍然返回 200（Nginx 缓存）
curl -I https://www.artimg.top  # HTTP/2 200
```

## 解决方案

### 方案一：Nginx 配置优化

在站点的 `location /` 中添加 `proxy_no_cache` 和 `proxy_cache_bypass`，禁止 Nginx 缓存 HTML 页面：

```nginx
location / {
    proxy_pass http://127.0.0.1:3100;
    # ... 其他配置 ...
    add_header Cache-Control "no-cache, no-store, must-revalidate" always;
    proxy_no_cache 1;
    proxy_cache_bypass 1;
}
```

> **说明**：原来只有 `add_header Cache-Control "no-cache..."` 只是告诉浏览器不缓存，Nginx 自身的 `proxy_cache` 仍然会缓存。加上 `proxy_no_cache 1` 和 `proxy_cache_bypass 1` 才能让 Nginx 也不缓存 HTML 页面。

`/_next/static/` 的缓存保持不变（文件名带 hash，每次构建会生成新文件名，缓存 1 年没问题）。

### 方案二：部署流水线自动清缓存

在 `.github/workflows/deploy.yml` 的部署脚本中，构建完成后自动清除 Nginx 缓存：

```yaml
# 清除旧构建缓存，确保全新构建
echo "[deploy] cleaning old build cache"
rm -rf .next

# 构建
echo "[deploy] building app"
pnpm build

# 清除 Nginx 代理缓存
echo "[deploy] clearing nginx proxy cache"
rm -rf /www/server/nginx/proxy_cache_dir/*

# 重启服务
echo "[deploy] restarting pm2 app"
pm2 restart next-pages-template || pm2 start ecosystem.config.cjs --only next-pages-template
pm2 save

# 重载 Nginx
echo "[deploy] reloading nginx"
nginx -s reload
```

### 手动清除缓存

如果遇到紧急情况需要手动清除缓存，SSH 到服务器执行：

```bash
rm -rf /www/server/nginx/proxy_cache_dir/*
nginx -s reload
```

## 关键知识点

| 项目 | 说明 |
|------|------|
| `NEXT_PUBLIC_` 变量 | 构建时内联到 JS bundle，不是运行时读取 |
| `add_header Cache-Control` | 只控制浏览器缓存，不影响 Nginx 自身的 proxy_cache |
| `proxy_no_cache 1` | 禁止 Nginx 将响应写入缓存 |
| `proxy_cache_bypass 1` | 让 Nginx 跳过缓存直接请求后端 |
| `/_next/static/` 缓存 | 文件名带 hash，可以安全地长期缓存 |
| `proxy_cache_dir` | 删除内容安全，Nginx 会自动重建缓存 |

## 缓存层级总结

```
用户浏览器 → Nginx proxy_cache → PM2 (Next.js)
    ↑               ↑                ↑
  浏览器缓存     Nginx 代理缓存    应用服务
  (Cache-Control)  (proxy_cache)   (源数据)
```

每一层都可能返回旧内容，排查时需要逐层确认。

# 支付前端接口调用文档

> 适用版本：v0.0.1
> 支付渠道：易收米
> 更新时间：2026-03-31

---

## 整体流程

```
1. 前端调用「创建订单并发起支付」接口
        │
        ▼
2. 后端返回 payUrl（支付链接）和 orderId
        │
        ▼
3. 前端将 payUrl 转成二维码展示给用户
   同时开始轮询订单状态
        │
        ▼
4. 用户扫码完成支付
        │
        ▼
5. 易收米通知后端（自动，无需前端参与）
        │
        ▼
6. 前端轮询到 status=paid → 支付成功，刷新积分
```



---

## 接口二：创建订单并发起支付（核心接口）

> 用户点击「购买」按钮时调用。后端同时完成建单和向易收米发起支付，一步返回支付二维码链接。

### 请求

```
POST /app/recharge/orders
Authorization: Bearer {jwt_token}
Content-Type: application/json
```

### 请求参数

```json
{
  "packageId": "pkg_100",  // 必填，套餐ID，从套餐列表接口获取
  "payType": 2             // 必填，支付方式
                           //   1 = 微信内支付（微信内置浏览器）
                           //   2 = 微信扫码支付（推荐，适合PC端展示二维码）
                           //   3 = 微信H5支付（手机浏览器跳微信）
                           //  11 = 支付宝H5支付
}
```

### 返回示例（成功）

```json
{
  "code": 200,
  "message": "创建订单成功",
  "data": {
    "orderId": 123,                                   // 本地订单ID，轮询时使用
    "orderNo": "RC202403311200001234",                 // 本地订单号
    "amount": 9,                                      // 订单金额（元）
    "points": 100,                                    // 购买成功后将获得的积分
    "packageName": "100积分套餐",                      // 套餐名称
    "payUrl": "weixin://wxpay/bizpayurl?pr=xxxxxx"    // 支付链接，转成二维码展示
  }
}
```

### 返回示例（失败）

```json
// 套餐不存在
{ "code": 404, "message": "充值套餐不存在" }

// 请求过于频繁（10秒内重复创建同一套餐）
{ "code": 429, "message": "创建订单过于频繁，请稍后再试" }

// 易收米接口调用失败
{ "code": 502, "message": "发起支付失败，请稍后重试" }
```

### 前端处理逻辑

```
1. 请求成功后，保存 data.orderId 用于后续轮询
2. 将 data.payUrl 传入二维码生成库（如 qrcode.js）生成二维码图片
3. 展示二维码弹窗，同时启动轮询（见接口三）
4. code !== 200 时展示错误提示
```

## 接口三：轮询订单状态

> 用户扫码后，前端通过轮询此接口感知支付结果，无需用户手动刷新。

### 请求

```
GET /app/recharge/orders/{orderId}
Authorization: Bearer {jwt_token}
```

| 参数 | 位置 | 说明 |
|------|------|------|
| orderId | URL路径 | 创建订单接口返回的 `data.orderId` |

### 返回示例

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "order": {
      "id": 123,
      "order_no": "RC202403311200001234",
      "amount": 9,                     // 订单金额（元）
      "points": 100,                   // 本次充值积分数
      "package_name": "100积分套餐",
      "status": "pending",             // 订单状态（见下方状态说明）
      "payment_channel": "yishoumi",
      "paid_at": null,                 // 支付时间，未支付时为 null
      "created_at": "2026-03-31 12:00:00"
    },
    "transactions": []               // 交易流水，可忽略
  }
}
```

### 订单状态说明

| status 值 | 含义 | 前端处理 |
|-----------|------|----------|
| `pending` | 待支付 | 继续轮询 |
| `paid` | 支付成功 | 停止轮询，提示成功，刷新积分 |
| `failed` | 支付失败（发起时失败） | 停止轮询，提示失败 |

### 轮询策略（推荐）

```javascript
const MAX_POLL_TIMES = 100;   // 最多轮询100次（约5分钟）
const POLL_INTERVAL_MS = 3000; // 每3秒轮询一次

let pollCount = 0;
let pollTimer = null;

function startPolling(orderId) {
  pollTimer = setInterval(async () => {
    pollCount++;

    // 超时停止
    if (pollCount > MAX_POLL_TIMES) {
      stopPolling();
      showMessage('支付超时，如已支付请稍后刷新页面确认积分');
      return;
    }

    const res = await fetch(`/app/recharge/orders/${orderId}`, {
      headers: { Authorization: `Bearer ${token}` }
    });
    const json = await res.json();
    const status = json?.data?.order?.status;

    if (status === 'paid') {
      stopPolling();
      closeQrModal();        // 关闭二维码弹窗
      refreshUserPoints();   // 刷新用户积分显示
      showMessage('支付成功，积分已到账！');
    } else if (status === 'failed') {
      stopPolling();
      showMessage('支付失败，请重新发起');
    }
    // status === 'pending' 时继续等待

  }, POLL_INTERVAL_MS);
}

function stopPolling() {
  if (pollTimer) {
    clearInterval(pollTimer);
    pollTimer = null;
  }
  pollCount = 0;
}

// 用户手动关闭弹窗时也要停止轮询
function onQrModalClose() {
  stopPolling();
}
```

## 接口四：查询积分余额（支付成功后刷新用户积分）

> 支付成功后调用，获取最新积分余额展示给用户。

### 请求

```
GET /app/points/logs?page=1&pageSize=1
Authorization: Bearer {jwt_token}
```

> 也可以调用用户信息接口获取 `points` 字段，具体以实际用户信息接口为准。

## 完整前端调用时序

```
用户点击「购买100积分套餐」
        │
        ▼
POST /app/recharge/orders
{ packageId: "pkg_100", payType: 2 }
        │
        ▼
返回 { orderId: 123, payUrl: "weixin://..." }
        │
        ├─ 将 payUrl 生成二维码，展示弹窗
        │
        └─ startPolling(123)  ← 开始每3秒轮询
                │
                ├─ GET /app/recharge/orders/123 → status=pending → 继续
                ├─ GET /app/recharge/orders/123 → status=pending → 继续
                ├─ GET /app/recharge/orders/123 → status=paid    → 成功！
                │
                ▼
        stopPolling()
        关闭弹窗 + 刷新积分显示
```

## 注意事项

| 事项 | 说明 |
|------|------|
| 二维码有效期 | 易收米生成的支付链接有时效，建议提示用户「请在5分钟内完成支付」 |
| 不要重复创建 | 用户点击购买后按钮应立即 disabled，防止重复创建订单 |
| 关闭弹窗时停轮询 | 用户关闭二维码弹窗时必须 clearInterval，避免内存泄漏 |
| 支付宝H5（payType=11） | 返回的是 HTTP 链接而非微信协议链接，直接跳转而非生成二维码 |
| 微信H5（payType=3） | 需在微信内置浏览器环境使用，普通浏览器无法唤起 |

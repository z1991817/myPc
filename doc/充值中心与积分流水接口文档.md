## 1. 通用说明

### 1.1 请求头

除非特别说明，本文档所有接口都需要登录态。

请求头：

```http
Authorization: Bearer <user_token>
```

### 1.2 通用返回格式

成功时通常返回：

```json
{
  "code": 200,
  "message": "ok",
  "data": {}
}
```

字段说明：

- `code: number`
  - 业务状态码
  - `200` 表示成功
- `message: string`
  - 提示信息
- `data: any`
  - 业务数据

失败时通常返回：

```json
{
  "code": 400,
  "message": "错误信息"
}
```

### 1.3 订单状态说明

当前代码里常见订单状态：

- `pending`
  - 待支付
- `paid`
  - 已支付

### 1.4 支付渠道说明

当前第一版主要是模拟支付，常见值：

- `mock`
  - 模拟支付渠道

## 2. 获取充值套餐列表

### 2.1 接口信息

- 方法：`GET`
- 路径：`/app/recharge/packages`
- 鉴权：需要

### 2.2 请求参数

无

### 2.3 成功返回示例

```json
{
  "code": 200,
  "message": "ok",
  "data": [
    {
      "id": "recharge_9_9",
      "name": "1000积分",
      "amount": 9.9,
      "points": 1000
    },
    {
      "id": "recharge_39_9",
      "name": "4500积分",
      "amount": 39.9,
      "points": 4500
    }
  ]
}
```

### 2.4 返回字段说明

- `data: RechargePackage[]`
  - 套餐数组

- `data[].id: string`
  - 套餐唯一标识
  - 创建订单时传给 `packageId`

- `data[].name: string`
  - 套餐展示名称

- `data[].amount: number`
  - 套餐价格
  - 单位通常为元

- `data[].points: number`
  - 购买后到账积分

### 2.5 前端用途

- 充值页套餐列表展示
- 创建订单前的套餐选择

## 3. 创建充值订单

### 3.1 接口信息

- 方法：`POST`
- 路径：`/app/recharge/orders`
- 鉴权：需要

### 3.2 请求体示例

```json
{
  "packageId": "recharge_9_9"
}
```

### 3.3 请求字段说明

- `packageId: string`
  - 套餐 ID
  - 必填
  - 必须是后端已配置的套餐标识

### 3.4 成功返回示例

```json
{
  "code": 200,
  "message": "创建订单成功",
  "data": {
    "order": {
      "id": 1,
      "order_no": "R202603300001",
      "user_id": 1001,
      "order_type": "recharge",
      "package_id": "recharge_9_9",
      "package_name": "1000积分",
      "amount": 9.9,
      "points": 1000,
      "status": "pending",
      "payment_channel": "mock",
      "third_party_order_no": null,
      "paid_at": null,
      "created_at": "2026-03-30 10:00:00",
      "updated_at": "2026-03-30 10:00:00"
    },
    "payment": {
      "channel": "mock"
    }
  }
}
```

说明：

- `data` 的准确结构以 [recharge.ts](D:/my-work/my-project/src/services/recharge.ts) 中 `createRechargeOrder` 的返回为准。
- 当前项目里至少可以确定会返回订单主信息，前端应以 `order.id` 和 `order.order_no` 作为后续支付和详情查询依据。

### 3.5 返回字段说明

- `data.order.id: number`
  - 订单主键 ID

- `data.order.order_no: string`
  - 业务订单号

- `data.order.user_id: number`
  - 下单用户 ID

- `data.order.order_type: string`
  - 订单类型
  - 当前一般为 `recharge`

- `data.order.package_id: string`
  - 套餐 ID

- `data.order.package_name: string`
  - 套餐名称

- `data.order.amount: number`
  - 支付金额

- `data.order.points: number`
  - 订单对应积分数量

- `data.order.status: string`
  - 订单状态
  - 常见值：`pending`、`paid`

- `data.order.payment_channel: string`
  - 支付渠道

- `data.order.third_party_order_no: string | null`
  - 第三方订单号

- `data.order.paid_at: string | null`
  - 支付时间

- `data.order.created_at: string`
  - 创建时间

- `data.order.updated_at: string`
  - 更新时间

- `data.payment: object`
  - 支付附加信息
  - 第一版通常用于告诉前端当前是模拟支付

### 3.6 失败返回

```json
{
  "code": 400,
  "message": "packageId 不能为空"
}
```

或：

```json
{
  "code": 404,
  "message": "套餐不存在"
}
```

或：

```json
{
  "code": 500,
  "message": "创建订单失败"
}
```

  - 例如 `pay`

  - 渠道交易号

- `data.transactions[].status: string`
  - 流水状态

- `data.transactions[].request_data: any`
  - 发起支付时记录的请求数据

  - 支付响应数据

  - 支付回调数据

  - 更新时间

```json
{
  "code": 404,
  "message": "订单不存在"

```

说明：

- 只能查看当前登录用户自己的订单详情。

## 8. 前端对接顺序建议

推荐按下面顺序对接充值中心：

1. `GET /app/recharge/packages`
   - 先把套餐页做出来
2. `POST /app/recharge/orders`
   - 点击套餐创建订单
3. `GET /app/recharge/orders`
   - 订单列表页
4. `GET /app/recharge/orders/{id}`
   - 订单详情页
5. `POST /app/recharge/orders/{id}/mock-pay`
   - 本地联调用
6. `GET /app/points/logs`
   - 积分流水页

## 9. 联调注意点

- `mock-pay` 仅适合开发环境联调。
- 订单列表和订单详情都只返回当前登录用户自己的数据。
- 积分流水是分页接口，前端要保留页码和每页条数状态。
- 创建订单成功后，建议前端直接跳订单详情页或拉起支付流程。
- 模拟支付成功后，建议刷新：
  - 当前用户信息 `GET /app/me`
  - 订单详情
  - 积分流水

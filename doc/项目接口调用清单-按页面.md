## 1. 全局请求规则（先看这个）

## 1.1 基础地址
- `api/request.ts` 使用 `axios.create({ baseURL: getApiBaseURL() })`。
- 当前 `.env` 配置：`NEXT_PUBLIC_API_BASE_URL=http://localhost:3000`。
- 所有相对路径（如 `/app/login`）最终会请求到 `http://localhost:3000/app/login`。

## 1.2 统一请求头
- 若本地有登录态 token（`useUserStore.token`），会自动追加：
  - `Authorization: Bearer <token>`

## 1.3 统一响应与错误处理
- 成功响应统一返回 `response.data`（不是 axios 原始响应对象）。
- `401`：清空用户态；若此前已登录则弹「登录失效，请重新登录」并打开登录弹窗。
- `409`：统一打开「积分不足」弹窗（`useInsufficientPointsModal`）。

## 3. 生图轮询机制（重点）

> 生图主流程在：`pages/create/index.tsx`。

## 3.1 关键常量
- `BANANA_SSE_FALLBACK_DELAY_MS = 5000`（SSE 首事件超时/降级等待）
- `BANANA_POLL_INTERVAL_MS = 3000`（轮询间隔）
- `BANANA_TASK_STORAGE_KEY = "banana-create-task"`（本地任务恢复 key）

## 3.2 主流程入口（点击“生成”）
1. 先清理旧任务状态：`stopBananaTaskTransport(true)` + 清除 localStorage 缓存。
2. 判断模式：
   - 图生图：`image-to-image`
   - 文生图：`text-to-image`
3. 判断模型：
   - Nano Banana 系列：先调 `/app/banana-CreateImage` 创建任务。
   - 非 Nano Banana：调 `/app/text-to-image` 或 `/app/image-to-image`，若响应里带 `taskId/queryPath` 同样走统一任务流。
4. 从创建响应提取 `taskMeta`：`taskId + queryPath + ssePath?`。
5. 进入统一执行器：`runBananaTaskFlow(taskMeta, prompt)`。

## 3.3 统一任务执行器 `runBananaTaskFlow` 逻辑
1. 生成 `runId`（用于并发防串线）。
2. 设置页面状态：`bananaTaskId`、`bananaTaskStatus`（默认 pending）。
3. 落盘缓存：`localStorage[banana-create-task] = { taskId, queryPath, ssePath, prompt }`。
4. 优先 SSE：若 `ssePath` 存在，调用 `waitBananaTaskBySSE`。
5. SSE 失败时降级：
   - 若是明确任务失败（`task_failed`）则直接抛错。
   - 若是超时/连接异常，则等待 5 秒后转 `waitBananaTaskByPolling`。
6. 终态处理：
   - `success`：清缓存、应用结果图片、刷新用户信息、清空 prompt。
   - `failed`：清缓存并弹错。
7. finally 中收尾：停止 SSE/轮询 transport，避免内存泄漏。

## 3.4 SSE 订阅细节 `waitBananaTaskBySSE`
- 通过 `bananaSubscribeTask(ssePath, token, onEvent)` 建立 SSE。
- 首事件超时机制：5 秒内没收到首条事件，判定 SSE 超时，交由外层降级轮询。
- 事件状态映射：
  - `task_success` => `success`
  - `task_failed` => `failed`
  - `ping` => `running`
  - 其他 => `normalizeBananaStatus(payload.status)`
- 一旦进入终态：
  - 关闭 SSE；
  - `failed` 抛业务错误；
  - `success` 返回任务结果。

## 3.5 轮询细节 `waitBananaTaskByPolling`
- 每 3 秒调用一次 `bananaQueryImage(queryPath)`。
- 状态标准化后只认两种终态：`success` / `failed`。
- 成功返回 `taskPayload`，失败抛错。
- 带 `inFlight` 锁，防止上次请求未结束又发新请求。

## 3.6 刷新页面后的断点续跑
1. 页面 hydration 且有 token 后，读取 `localStorage[banana-create-task]`。
2. 先立即请求一次 `bananaQueryImage(queryPath)`：
   - 若已 `success`：直接渲染结果并清缓存。
   - 若已 `failed`：清缓存并提示失败。
   - 若仍进行中：调用 `runBananaTaskFlow(..., { skipPersist: true, initialStatus })` 继续追踪。

## 3.7 成功结果如何落图
- `applyBananaSuccessResult` 优先展示 `previewUrl`，并后台预加载 `cosUrl`。
- 若 `previewUrl` 与 `cosUrl` 不同，高清图加载完成后自动替换为 `cosUrl`。
- 同步调用 `refreshCurrentUser({ silent: true })` 刷新积分。

## 3.8 当前实现说明
- `waitForImageTask`（基于 taskId 的通用轮询函数）目前在 `create` 页未被实际调用。
- 当前线上主逻辑是 `queryPath + ssePath` 的任务跟踪模型。

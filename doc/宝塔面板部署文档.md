# Next.js 项目宝塔面板部署文档

本文档用于将当前项目部署到云服务器的宝塔面板环境，并通过 `Nginx + PM2 + Node.js` 运行。

适用信息：

- 项目类型：Next.js
- 构建命令：`npm run build`
- 启动命令：`npm run start`
- 服务端口：`3100`
- 接口环境变量：`NEXT_PUBLIC_API_BASE_URL`
- 当前接口地址：`http://43.133.54.166/`

项目中接口地址读取位置：

- `lib/axios.ts`
- `api/request.ts`

代码里已经支持通过环境变量读取接口地址：

```ts
baseURL: process.env.NEXT_PUBLIC_API_BASE_URL || "http://localhost:3000"
```

因此，部署时只需要正确配置环境变量并重新构建即可。

---

## 1. 部署目标

部署完成后，访问方式如下：

- 用户通过域名或服务器 IP 访问 Nginx
- Nginx 将请求反向代理到 Next.js 服务
- Next.js 服务运行在 `3100` 端口
- 前端接口请求转发到 `http://43.133.54.166/`

推荐部署结构：

```text
浏览器 -> Nginx(80/443) -> Next.js(127.0.0.1:3100)
```

## 2. 服务器环境要求

建议服务器环境：

- Linux 服务器一台
- 已安装宝塔面板
- 已安装 Nginx
- 已安装 Node.js 20.x
- 已安装 PM2

建议开放端口：

- `80`
- `443`

说明：

- `3100` 端口不建议直接对外暴露
- 正式环境建议只开放 `80/443`，由 Nginx 反向代理

## 5. 配置环境变量

本项目使用环境变量 `NEXT_PUBLIC_API_BASE_URL` 作为前端请求地址。

在线上服务器项目根目录创建文件：

```bash
.env.production
```

文件内容如下：

```env
NEXT_PUBLIC_API_BASE_URL=http://43.133.54.166/
```

说明：

- 文件必须放在项目根目录
- 必须与 `package.json` 同级
- 改完环境变量后，需要重新执行 `npm run build`
- `NEXT_PUBLIC_*` 变量会在前端构建时注入，不能只改文件不重建

你也可以先检查文件是否已经存在：

```bash
cd /www/wwwroot/next-pages-template
cat .env.production
```

## 9. 配置宝塔站点

Next.js 项目不能直接当成普通静态 HTML 网站使用，需要通过 Node.js 服务运行。

因此在宝塔里要做的是：

1. 新建一个网站
2. 让 Nginx 处理外部访问
3. 将网站请求反向代理到 `127.0.0.1:3100`

### 新建站点

在宝塔面板中：

1. 打开“网站”
2. 点击“添加站点”
3. 输入你的域名，或者直接使用服务器 IP
4. PHP 版本选择“纯静态”

说明：

- 这里的“纯静态”只是宝塔站点类型
- 真正的页面仍然由 Next.js 服务生成
- Nginx 只是代理入口

---

## 10. 配置反向代理

在宝塔中进入站点设置，添加反向代理：

- 代理名称：`next-app`
- 目标 URL：`http://127.0.0.1:3100`
- 发送域名：`$host`

如果你手动编辑 Nginx 配置，可参考：

```nginx
server {
    listen 80;
    server_name 你的域名或服务器IP;

    location / {
        proxy_pass http://127.0.0.1:3100;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

说明：

- `proxy_pass` 指向本机 Next.js 服务
- `Upgrade` 和 `Connection` 头用于兼容部分长连接场景
- `Host` 头保留原始域名信息

## 13. 常见问题排查

### 13.1 页面打不开

检查项：

1. `pm2 list` 是否有运行中的进程
2. `pm2 logs next-pages-template` 是否有报错
3. Nginx 是否启动
4. 域名是否正确解析到服务器

### 13.2 宝塔反向代理后出现 502

通常原因：

1. Next.js 服务没有启动
2. `3100` 端口没有监听
3. PM2 进程崩溃
4. 反向代理地址配置错了

排查命令：

```bash
pm2 list
pm2 logs next-pages-template
ss -lntp | grep 3100
curl http://127.0.0.1:3100
```

### 13.3 接口请求还是 localhost

通常原因：

1. `.env.production` 没放在项目根目录
2. 环境变量名称写错
3. 改完变量后没有重新构建

正确变量名：

```env
NEXT_PUBLIC_API_BASE_URL=http://43.133.54.166/
```

改完后重新执行：

```bash
npm run build
pm2 restart next-pages-template
```

### 13.4 出现跨域问题

如果前端域名和接口地址不是同源，后端需要正确配置 CORS。

例如你的前端是：

```text
http://yourdomain.com
```

接口是：

```text
http://43.133.54.166/
```

那么后端必须允许你的前端域名跨域访问。

### 13.5 前端站点是 HTTPS，接口还是 HTTP

如果未来前端站点使用 `https://`，而接口还是：

```text
http://43.133.54.166/
```

浏览器可能会因为混合内容策略直接拦截请求。

解决方式：

1. 给接口也配置 HTTPS
2. 或将接口通过同域名 Nginx 反向代理为 `/api`

## 14. SEO 与服务端渲染说明

本项目是 Next.js，部署到 Node.js 服务环境后，具备服务端渲染能力。

这意味着：

- 不能仅上传到普通静态空间
- 必须运行 `next build` 和 `next start`
- 必须放在可以运行 Node.js 的服务器环境中

当前宝塔部署方式正是标准做法：

```text
Nginx + Node.js + PM2 + Next.js
```

说明：

- 这是支持 SEO 的部署方式
- 但“能 SSR”不等于“SEO 已做好”
- 如果要进一步优化 SEO，还需要为页面补充 `title`、`description`、语义化结构、sitemap、robots.txt 等内容
